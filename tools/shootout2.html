Regex Shootout 2

Tier list

Correctness gates the top three tiers: an engine with any open bug in the irx ledger can place no higher than C. Within each half, an engine earns one step for being fast (geometric-mean search time at most × Rust's) and one for being featureful (at least of the 14 construct families below, read from irx's dialect model).

Which inputs

Overall speed

Each engine's search time divided by Rust's on the same input, combined as a geometric mean over the inputs chosen above. Bars right of the line are slower than Rust. Engines differ in what they can run: POSIX engines reject lazy quantifiers and \b, DFA engines reject Unicode word boundaries, and timeouts count as not run, which is why the strict view compares engines only on shared inputs.

Where the time goes

The same ratio, split four ways: ASCII against Unicode patterns and subjects, inputs Rust accepted against inputs it rejected, and four subject sizes (16, 128, 1,024 and 8,192 characters). A cell compares the engine with Rust on that slice only, so a row shows how an engine's speed changes, not which slice is slow overall.

The full matrix

All three splits crossed: for each engine, ASCII or Unicode, an input Rust accepted or rejected, and the subject size. Each cell is the geometric-mean ratio to Rust over the 125–170 inputs in that slice. Reading across a block shows how an engine scales with size; comparing the accept and reject blocks shows whether it is quicker to find a match or to rule one out.

Scaling with input size

Absolute median time per search at each size, ASCII set, for a selection of engines (log scales). A slope of one decade per decade is linear in the input; Rust's lazy DFA and Hyperscan-style engines stay flat on short inputs because per-call overhead dominates.

Features

Construct families each engine supports, from the irx dialect that models it (irx features). These are what the fuzzer generates for that engine, so they reflect tested support.

Correctness

Open bugs in the irx ledger that affect each engine. Engines that embed a library inherit its bugs (PHP and Erlang run PCRE2; SpiderMonkey runs V8's Irregexp). Zero means irx has not found one, across self-checks, campaigns and the cross-engine check, not that none exist.
