# Bug ledger recheck, 2026-10-15

Every regex bug in the ledger was rerun on its original engine at the version installed on 2026-10-15, and its headline repro was run on every other installed engine (54 engine configurations, through irx's hosts with one case per process where a batch failed; hangs time out). Hand checks in a fresh process cover what the hosts cannot express (Perl state, Java regions, PCRE2 start offsets, Swift semantics, Emacs `rx`, Rhombus, nim-regex compile time, lone surrogates, `d`-flag indices, engine262). Non-regex rows (CSS selectors, DOM, LLVM GlobalISel, Chibi macros, FileCheck: 15 rows) are not covered.

**Original engine:** 137 reproduce; 9 are newly fixed; 17 were already resolved and stay fixed; 2 partly fixed; 5 not tested.

## Doubtful or duplicate entries

- **IRX-PCRE2-2** (`(?:^\B|..){0,2}\S` on `" .-x0"`, PCRE2 `[0,3)`, ledger expects `[0,5)`): engines split. `[0,3)` also from PCRE 8.45, PHP, Erlang, ICU4C 78.3, NSRegularExpression, Ruby 4.0.7, fancy-regex 0.19.2, nim-regex 0.27.0 and Swift Regex; `[0,5)` from Perl, Python `re`/`regex`, Java, .NET, Oniguruma 6.9.10, Boost and the JS engines. It turns on whether an empty iteration of a bounded loop ends the loop; PCRE2 unrolls bounded loops (irx models this since af2c9be). Likely implementation-defined rather than a PCRE2 bug.
- **IRX-PCRE2-7** (`(?<=(?>a|))a` on `"a"`): the row cites Perl for the expected match, but Perl 5.44.0 and blead give no match, as does OpenJDK 27. Only right-to-left lookbehind semantics (ECMAScript) give a match.
- **IRX-DOTNET-13** is the same bug as imported **DOTNET-4** (dotnet/runtime #135329): `(?:a+|)+` on `""` and `(?:a+|){5}` on `"aaaa"` fail on .NET 11.0.0-rc.1 and pass on 9.0.4, and NonBacktracking fails too (IRX-DOTNET-13 says interpreter and Compiled only).
- **IRX-FANCY-1** cites Perl for group 1 `Some(0..1)` on `(?:(?:(a)|b)(?=)){2}` / `"ab"`; Perl 5.44.0 and blead leave group 1 unset (PCRE2 gives `0..1`). The bug itself stays resolved in fancy-regex 0.19.2.
